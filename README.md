# Low-latency speech recognition with Whisper

Live captions need to show words while someone is still speaking. One way to do that is to transcribe overlapping slices of audio. The overlap gives the recognizer some context, but it can also make captions repeat words or lose them where two slices meet.

This project is a local benchmark for engineers building live captions, meeting transcription, or voice interfaces. It compares ways to join overlapping transcripts and shows how to tell a stitching error from a repetition already generated by the recognizer.

**Speech foundation model.** The original pilot and the follow-up both used [OpenAI Whisper](https://arxiv.org/abs/2212.04356), specifically its English-only `openai/whisper-tiny.en` checkpoint. Both used the pretrained model as-is to test how transcript stitching affects accuracy.

## What the pilot found

**Using the known overlap worked better than estimating it with Dynamic Time Warping (DTW).** With the same chunk transcripts and text-matching rules, fixed overlap reduced insertions from 820 to 763. It had lower word error on six utterances and tied on fourteen.

| Method | Corpus word error rate ↓ |
| --- | ---: |
| Full-utterance Whisper | 7.59% |
| Naive chunk concatenation | 712.95% |
| Text-only stitching | 546.88% |
| DTW-guided stitching | 218.30% |
| Fixed overlap + text matching | 205.36% |

The pilot used Whisper Tiny English on 20 read-speech utterances from one speaker. Each chunked method used 1.2-second windows with a 400 ms stride. Error rates can exceed 100% because every extra word counts as an insertion. In one failure, Whisper generated 359 words from a single window before stitching began.

For an engineering team, the distinction matters. Changing the merge rule can remove duplicated overlap, while decoder loops call for changes to the decoding or buffering policy. The pilot measures decoding time separately from the time a listener waits for a caption. See the [benchmark report](report/short_report.md) for the error breakdown, a failure example, and a test plan for live systems.

## Run the pilot locally

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
PYTHONPATH=src python scripts/evaluate_dummy_dataset.py \
  --dataset hf-internal-testing/librispeech_asr_dummy \
  --config clean --split validation --limit 20 \
  --model openai/whisper-tiny.en \
  --chunk-ms 1200 --stride-ms 400 \
  --results results/whisper-tiny-stitching.json
```

The first run downloads the dataset and model. Inference runs locally on CPU. The JSON includes raw chunk transcripts, per-utterance scores, and corpus totals for substitutions, deletions, and insertions.

## Test bilingual speech

Use the multilingual Whisper Tiny and Small checkpoints to compare Spanish, English, and mixed-language clips. The [bilingual benchmark guide](report/bilingual-benchmark.md) explains how to prepare local audio and compare the results by condition.
